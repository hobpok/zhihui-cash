# 修改意见模板

复制后直接在聊天或文档中填好，交给项目负责人即可，不需要GitHub账号。

```text
评审版本：6-0.28.0（可另附看到的提交SHA）
评审范围：业务口径 / 操作流程 / 界面 / 可解释性 / 测试 / 其他
理解摘要：用3至5句说明项目目标与完整业务路径。

建议1：简短标题
优先级：高 / 中 / 低
依据：具体文件、函数或界面路径；可复现时列出样例与操作步骤。
现状：观察到的行为，区分已经证实与推断。
影响：谁在什么情况下会受影响。
建议：希望改成什么；涉及规则时明确分母、时点、对象与边界。
验收：改完如何检查，包括至少一个关键边界。
待确认：缺少什么信息；没有则写无。

建议2至5：同上。
总体未验证范围：例如没有运行页面、没有测试移动端。
```

优先使用仓库已有模拟数据说明问题。不要附实际账户、密码、生产存档或私人材料。对源于旧fixture／设计图的观察，先核对现行代码，避免把历史样例当成当前默认行为。
