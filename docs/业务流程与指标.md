# 业务流程与指标

本文描述6-0.38.0模拟合同，便于业务评审，不是现实制度的适用性判断。应用版本更新至6-0.38.0，版本初始化标记保留6-0.28.0：已初始化账号不重置，未初始化账号沿用既有一次初始化流程。本地静态演示不提供生产登录。

## 工作流

1. **初始数据**：选择演示模板，检查基金净值、账户现金、持仓、银行参数、到期收付与计划。
2. **编制计划**：经理记录目标金额和业务类型，必要时由AI提出候选；候选不能代替人工决策。
3. **计算与复核**：确定批次、顺序和可执行金额，展示现金、敞口和期限影响，以及阻断／缺失数据原因。
4. **下达**：人确认计算依据后生成模拟指令；在途承诺占用额度。撤改申请本身不释放占用。
5. **投管模拟**：录入成交，再以“结算”一并登记结算及到账／付款；历史已结算未到账的余款可通过同一入口补记，不重复记款。已成交待收与已到账不能混记；实际付款仍受账户现金限制。
6. **重新计算**：成交和收付改变状态后重新计算，保留指令与历史，核对目标是否完成、指标是否达标。

业务实时头寸纳入当日到期款及已确认应收／融资等口径；账户现金表示实际已收付余额。款项到账不能重复增加已计入的业务头寸，支付已保留的应付也不能重复扣减。计划完成与所有指标达标是两个状态。

## 可切换初始样例

金额单位为亿元，均为合成演示，基金NAV均为500亿元。

| 项目 | 三项银行约束（默认） | 原始样例（零现金／成农商6%） |
|---|---|---|
| 模板 | `SIM-DEFAULT-COMPANY-GATES-20261019`，revision 2 | `SIM-DEFAULT-COMPLEX-01`，保持原内容 |
| 初始账户现金 | 5 | 0 |
| 计划数 | 6 | 9 |
| 核心观察点 | 公司级新增存款门槛与本基金5%独立约束；存款／存单顺序 | 成农商先存6亿使公司敞口66/1100=6%，再买存单1亿 |
| 默认计划 | 广州卖90天存单2、存3；江南存2、买存单1；逆回购20（7天）；融资49（1天） | 卖中原存单13；成农商存6；中原存单7.5；广州存单1；成农商存单1；非银行短融各1（60／90天）；融资17.6（1天）；逆回购13.1（7天） |
| 完整模拟后的账户现金 | 5（含偿还旧融资25） | 0 |
| 完整模拟后C02 | 5% | 5.02% |
| 完整模拟后C09 | 46700/549≈85.06375228天 | 46281.3/517.6≈89.41518547天 |

默认样例初始资产525亿、负债25亿。原资产快照期限88天，日初计应还款后的业务期限92.4天；不是同一口径下发生了数值矛盾。初始业务头寸5−25=−20亿，C02为0%；最终C02含现金与一年内政府债，并非只算账户现金。

“原始样例”内置于源码，不需要原文件或云端下载；它不是此前已经更正的七笔误规则场景。切换会保留旧运行历史并新建所选运行，规则不倒退。

另有“补救案例（未预设卖券）”，与默认样例持仓和参数相同，仅去掉广州卖CD的预设计划，初始为5笔。它用于验证系统能否发现补救，而非读取预先写好的卖券目标。点击“计算并刷新建议”后，存款仍未安排时搜索同银行CD／银行债；广州案例候选为卖90天CD 2亿元，实际成交后公司敞口79−2=77亿元，再整笔存3亿元至80／1000=8%。融资49亿元、逆回购20亿元及全部原投资目标保留。候选逐步路径通过现有求解器核验，经理明确勾选同意后才加入计划，随后仍须重新计算、审核和手动下达；加入或下达都不是成交，不释放实际额度。

补救发现扣除已有卖券、已成交和在途占用，只使用已知可卖量；同银行CD优先，支持多券组合和银行债。默认扫描最多8项持仓、24个候选，未找到或预算截断不能解释为全局无解。缺关键数据不补0；用户明确禁卖时不自动生成新卖券。此轮不做任意资产优化或自动卖长换短。

## 当前核心约束

完整实现与边界判断见 [core-rules.js](../app/core-rules.js) 及测试。主要口径如下：

| 规则 | 当前模拟含义 |
|---|---|
| C01 | 业务头寸非负；不等同账户现金 |
| C02 | 现金及一年内政府债占NAV至少5%；注意业务头寸／已收付口径 |
| C03／C04 | 本基金同银行存款＋存单：无托管资格不超过NAV5%，有托管资格不超过20% |
| C05 | 全公司货基同银行存款＋存单＋银行债不超过该银行季度净资产10% |
| C05-DEPOSIT | 新增存款后，同一公司级敞口不超过该银行配置上限，通常6%，合成批准后可设8%；等于上限允许 |
| C06 | 同一有托管资格银行全部金融工具不超过本基金NAV15% |
| C07／C08 | 同一BB或BB-银行全部敞口分别受本基金NAV2%、该银行净资产5%约束 |
| C09 | 资产、负债与正回购调整后的平均剩余期限不超过90天；按当前样例日历合同解释 |

新增存款门槛只在新增存款动作上检查，存单仍会改变公司敞口并影响下一笔存款。默认广州合成批准8%、江南6%，两行同时受无托管资格银行本基金5%约束。两条链的正确方向不同：

- 广州初始公司敞口79亿元／季度净资产1000亿元=7.9%。先卖90天存单2亿元，敞口降至77/1000=7.7%；再整笔存3亿元，到80/1000=8%，等于上限允许。直接存3亿元会到82/1000=8.2%，被阻断。
- 江南初始58/1000=5.8%。先整笔存2亿元，到60/1000=6%，允许；再买存单1亿元到61/1000=6.1%，不触发新增存款专用门槛，但仍须满足其他规则。逆序先买存单会到5.9%，再存2亿元到6.1%，存款被阻断。

新增存款在计算、下达、成交和撤销环节均按整笔处理，不能按可执行容量拆小绕过门槛。历史已有部分成交的存款指令保留成交事实，剩余金额作为一整笔处理。其他品种仍可在满足规则和现金等条件时安全部分成交。投管界面提示实际成交所需顺序，并按当时实际状态拦截受限动作；计算时安排了前置交易，不等于其已经成交。

银行名称只是演示标签，资格、评级、季度净资产并非已核实的银行事实。

当前单日模型支持“渐进改善”：对参与趋势比较的适用C01–C09指标，候选至少改善一项且其他指标均不恶化时，尚未完全达标的相关步骤可带警告放行。融资与卖券统一按本笔实际成交后的头寸测算；初始负20亿元头寸下两类流入可优先下达，成交才按实际金额计入，到账不重复改善。缺失数据、其他阻断或实际付款现金检查仍有效。具体条件见 `core-rules.js` 的候选趋势判断。

金额使用人民币元整数；比例按字段合同（如 `depositLimitBps` 使用基点，600=6%）。阈值判断优先使用整数交叉乘积；缺失敞口、分母、期限等应返回缺失或待确认，不能用0替代。期限字段的历史命名含 `TradingDays`，但当前单日样例使用明确的 `day-365-demo-v1` 日历合同，不能仅凭字段名推断真实交易日口径。

## AI的角色

AI可解释现状、提出候选计划或排序建议；顺序解释须包含正向与反向的敞口数字，明确广州先卖后存、江南先存后买，以及存款不可拆分的原因。流式文字是临时预览；最终结构验证和保存通过后才形成可确认候选。加入计划之后仍须人计算、复核和下达。公开本地演示不连接真实AI；后端相关代码及隔离测试用于解释设计。

当前比例达标、下一笔交易可推进、全部计划完成是三个问题。当前C02为22／500亿元时达到5%还差3亿元；若拟下广州3亿元存款，则考虑本笔用款后需再成交融资6亿元。账户已有5亿元足以支付3亿元时，不仅为付款要求全部融资到账；其他规则、真实可付款余额及手工复核仍须满足。相关核验仅在独立副本上模拟，不改变原运行。

AI诊断区分金额／比例／对象／现金口径错误、缺少或未知引用、旧依据和内部解释失败。部分解释错误有一次有界修复，失败可保留经校验的可信工具摘要；缺引用可按本轮有效工具记录重建摘要并重验。未知引用、过期依据、缺必需工具、无效候选或结构不能借恢复绕过校验。页面明确展示恢复结果和请求编号；依据过期应先保存当前运行、重新测算，内部解释失败可保留需求重试。
